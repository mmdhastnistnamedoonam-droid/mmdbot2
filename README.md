# رباتِ تلگرام — اجرا روی GitHub Actions با راه‌انداز Cloudflare (رایگان)

**چطور کار می‌کنه؟**
- کدِ ربات (پایتون) روی **GitHub Actions** اجرا می‌شه. هر نوبت حدودِ ۵ ساعت و ۴۰ دقیقه‌ست.
- یه **Worker رایگانِ کلودفلر** هر ۵ دقیقه چک می‌کنه؛ اگه ربات خاموش بود روشنش می‌کنه و ته‌ِ هر نوبت، نوبتِ بعدی رو از قبل توی صف می‌ذاره.
- دیتابیس (`bot_data.db`) آخرِ هر نوبت و هر ۵ دقیقه یه‌بار توی **Cloudflare KV** (رایگان) ذخیره می‌شه و نوبتِ بعدی ازش ادامه می‌ده.
- پیام‌هایی که وسطِ تعویضِ نوبت (حدودِ ۱ دقیقه) بیان از دست نمی‌رن؛ تلگرام نگه‌شون می‌داره و ربات بعدش جواب می‌ده.

## راه‌اندازی (یک‌بار)

### ۱) ریپوی GitHub
یه ریپویِ **Public** بساز و همه‌یِ فایل‌هایِ این پوشه رو توش بریز (`.gitignore` جلویِ آپلودِ دیتابیس و توکن رو می‌گیره).
> چرا Public؟ ریپویِ Private فقط ۲۰۰۰ دقیقه در ماه اجرایِ رایگان داره (حدودِ ۳۳ ساعت)، ولی Public نامحدوده.
> توکن و دیتابیس توی کد نیستن؛ توی Secrets و KV هستن و برایِ بقیه دیده نمی‌شن.

### ۲) ساختنِ توکن‌ها
- **کلودفلر:** My Profile ← API Tokens ← Create Token ← قالبِ **Edit Cloudflare Workers** (این قالب دسترسیِ KV هم داره). و **Account ID** رو از داشبوردِ Workers بردار.
- **گیت‌هاب (PAT):** Settings ← Developer settings ← Fine-grained tokens ← فقط همین ریپو، دسترسیِ **Actions: Read and write**.
- **تلگرام:** توکنِ ربات از @BotFather (بهتره توکنِ جدید بگیری) و آیدیِ عددیِ خودت از @userinfobot.

### ۳) Secrets
ریپو ← Settings ← Secrets and variables ← Actions ← New repository secret:

| اسم | مقدار |
|---|---|
| `BOT_TOKEN` | توکنِ ربات |
| `OWNER_ID` | آیدیِ عددیِ مالک |
| `CLOUDFLARE_API_TOKEN` | توکنِ کلودفلر |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID |
| `LAUNCHER_GH_PAT` | توکنِ گیت‌هاب (PAT) |

### ۴) (اختیاری) انتقالِ دیتابیسِ قبلی — **قبل از مرحلهٔ ۵**
روی کامپیوترت، کنارِ فایلِ `bot_data.db`:
```
pip install requests
CF_API_TOKEN=توکنِ_کلودفلر CF_ACCOUNT_ID=آیدی_اکانت python ops/kv_store.py push bot_data.db
```
(روی ویندوز: اول `set CF_API_TOKEN=...` و `set CF_ACCOUNT_ID=...` و بعد دستورِ python.)
ربات‌ِ قدیمی رو هم خاموش کن؛ تلگرام دو نمونه‌یِ هم‌زمان رو قبول نمی‌کنه.

### ۵) روشن‌کردن
ریپو ← Actions ← **deploy-launcher** ← Run workflow. (بعدش خودش با هر تغییرِ پوشهٔ `launcher` دیپلوی می‌شه.)
حداکثر تا ۵ دقیقه بعد، Worker ربات رو راه می‌اندازه. می‌تونی دستی هم بزنی: Actions ← **bot** ← Run workflow.

## کارهایِ روزمره
- **دیدنِ وضعیت:** Actions ← bot؛ باید یه اجرایِ سبزِ در حالِ اجرا باشه.
- **خاموش‌کردن:** Worker رو از داشبوردِ کلودفلر (Workers ← mmd-bot-launcher ← Settings ← Triggers) غیرفعال کن و اجرایِ فعلی رو Cancel کن.
- **گرفتنِ دیتابیس:** `python ops/kv_store.py pull bot_data.db` (و `status` برایِ دیدنِ زمانِ آخرین نسخه).
- **لاگِ ربات:** چون ریپو عمومیه، لاگِ ربات (آیدیِ کاربرها) عمداً روی صفحهٔ Actions چاپ نمی‌شه. برایِ عیب‌یابیِ موقت: Settings ← Variables ← `DEBUG_LOGS` = `1` (بعدش پاکش کن).
- بک‌آپِ روزانهٔ خودِ ربات (ساعتِ ۱۴:۰۰ تهران) هنوز برایِ مالک توی تلگرام فرستاده می‌شه؛ نسخهٔ دومِ ایمنیه.

## محدودیت‌هایِ این روش (مهم)
- **قوانینِ گیت‌هاب:** استفاده از Actions برایِ اجرایِ دائمیِ یه ربات، خارج از هدفِ رسمیِ سرویسه و گیت‌هاب می‌تونه جلویش رو بگیره یا اکانت رو محدود کنه. اگه ربات برات مهمه، بک‌آپ‌ها رو جدی بگیر.
- **وقفهٔ کوتاه:** هر ~۵ ساعت و ۴۰ دقیقه، حدودِ ۱ دقیقه ربات جواب نمی‌ده (پیام‌ها از بین نمی‌رن).
- **آخرین ≤۵ دقیقهٔ دیتا:** اگه گیت‌هاب ماشین رو ناگهانی بکشه (نه با توقفِ عادی)، تغییراتِ آخرِ ۵ دقیقه ممکنه برنگرده.
- **حجمِ دیتابیس:** KV تا ۲۵MB برایِ هر مقدار می‌ذاره؛ دیتابیس بعد از فشرده‌سازی باید زیرِ ~۱۸MB بمونه. اگه بزرگ‌تر شد، خطا توی لاگِ runner می‌بینی.
- **سقفِ رایگانِ KV:** ۱۰۰۰ نوشتن در روز؛ این طراحی حداکثر ~۵۷۶ تا مصرف می‌کنه.

## اجرایِ قدیمی (سرورِ شخصی)
هنوز کار می‌کنه: `bash install_bot.sh` (سرویسِ systemd) — ولی هیچ‌وقت هم‌زمان با نسخهٔ GitHub روشنش نکن.

## چی حذف/بی‌اثر شده (نسخهٔ مستقل)
- پوش و Firebase، ذخیرهٔ رسانه برایِ سایت، لینکِ ورودِ اپ، جاب‌هایِ مخصوصِ سایت/اپ، ورودِ مالک با یوزرنیم/پسوردِ سایت (به‌جاش `OWNER_ID`).
- سرِ جاشه: مدیریتِ گروه/هشتگ/محتوا، کول‌داون و ضدِ فلود، ادمین/VIP، ناحیه‌ها و فرمانده‌ها، اکسل، بک‌آپِ روزانه.
